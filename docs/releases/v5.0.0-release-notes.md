# Nightshade 5.0.0

Version 5.0.0 (build 23)

Nightshade 5.0 is built around one idea: your sky should be *yours*. The headline
is **Living Sky** — a personal, growing atlas of everything you've imaged, a
"First Light" path that turns a night's captures into real scientific
contributions, and a Constellation mode that lets more than one rig work the same
target together. Alongside that, cloud backup grows beyond WebDAV to any
S3-compatible store, and there's a deep, mostly-invisible layer of reliability,
safety, and security work underneath it all. The notes below walk through what
changed.

## Living Sky

### Your Sky — an atlas that grows as you image

Your Sky is a personal atlas. Every target you capture is added to it, and the
map fills in over time as a record of where you've actually pointed and what you
collected. You can name regions, watch coverage grow, and come back to a part of
the sky you've built up across many nights instead of treating each session as a
blank slate.

### First Light — from a capture to a real contribution

First Light turns imaging into something you can publish. When a session surfaces
a transient, a variable star, or a minor planet, Nightshade can package the
evidence and submit it to the appropriate catalog — TNS for transients, AAVSO for
variable-star photometry, the Minor Planet Center for astrometry — through a real
submission path, not a placeholder. The emphasis throughout is honesty: the app is
careful to only present a measurement as science when it actually is one, and to
show its working rather than a confident-looking number it can't stand behind.

### Constellation — more than one rig on the same sky

Constellation lets a set of rigs cooperate. One machine coordinates while others
join in, contribute their raw sub-frames, and share the load on a region. Rigs
advertise their reachability so you can see who's actually available, regions can
be claimed and retracted cleanly, and the raw sub-frames each rig captures are
shared rather than siloed — so the group's data lands in one place. Master and
slave roles stay in parity, so what you see on the coordinator matches what the
contributors are doing.

## Cloud backup: now any S3-compatible store

Cloud backup previously spoke only WebDAV (Nextcloud, ownCloud, and similar). It
now also speaks **S3**, so you can point your backups at Amazon S3, a self-hosted
MinIO server, or Backblaze B2.

In **Settings → Backup & Sync**, pick your provider, enter the endpoint, region,
bucket, and access key, and your secret key. There's a path-style toggle for MinIO
and other self-hosted gateways. Use **Test Connection** to confirm your
credentials and bucket before saving, then backup push/pull, auto-push, and
restore all work exactly as they did with WebDAV. Your secret key is stored in the
operating system's keyring, never in app settings or logs.

Existing WebDAV setups are untouched — if you've already configured cloud sync,
nothing changes and you don't need to do anything.

## Reliability, safety, and security

A large share of this release went into hardening the parts of Nightshade you
don't see but rely on. The highlights, in plain terms:

- **Remote control is harder to abuse.** The headless server now ties its
  rate-limiting and lockout to the real network connection rather than a header a
  client could forge, checks authentication before it buffers a request body,
  throttles pairing and websocket attempts, and tightens its file-path validation
  so the file-browse and validate endpoints can't be coaxed into probing paths
  outside the folders you've allowed.
- **Updates fail closed.** The auto-updater now requires a valid cryptographic
  signature on an update before it will apply it, and re-verifies that signature at
  the moment it installs — not just an easily-recomputed hash. An unsigned or
  tampered update is refused rather than trusted. (Operators: this means update
  packages must be signed and the signing key provisioned; otherwise auto-update
  stays safely disabled.)
- **Your gear won't be double-commanded.** Non-idempotent hardware commands — a
  relative focuser/rotator move, a mount slew, an exposure — are now sent exactly
  once even over a slow or flaky remote link, so an impatient retry can't actuate
  your equipment twice.
- **Sessions clean up after themselves.** The sequencer now reliably reaps
  timed-out child processes (and their process groups) instead of leaking them,
  and a number of leaked images, controllers, and subscriptions on the mobile and
  desktop sides were fixed.
- **Better error reporting.** Errors surfaced over the remote API now carry a
  stable machine-readable code alongside the human message, in a
  backward-compatible envelope, so clients can react to *what* went wrong instead
  of string-matching.

## Under the hood

- **Imaging correctness.** Master-frame accumulation got overflow-checked geometry,
  corrected cross-fold frame weighting, and a more robust online clipping-variance
  path — improvements to the math behind your stacked masters, with the on-disk
  format unchanged.
- **A quieter, tighter codebase.** A broad cleanup removed proven-dead code and
  duplicate paths, deduplicated logic that had drifted apart, and replaced a batch
  of weak or self-referential tests with ones that assert real behavior — so the
  app is easier to keep correct going forward.
- **Device hot-plug** events were promoted to first-class events end to end, so the
  app reacts more cleanly when gear is connected or removed mid-session.
- **Build and release** were brought in line: versions are reconciled across the
  workspace and guarded by a consistency check, and the Linux release artifact now
  matches the runnable bundle layout.

## Upgrade notes and compatibility

- **Existing configuration is preserved.** Saved profiles, sequences, cloud-sync
  setups, and layouts carry forward. There is no database migration in this
  release.
- **Auto-update requires signed packages.** Because updates now fail closed on an
  invalid signature, a build that isn't signed (with the signing key provisioned)
  will not auto-update. This is deliberate.
- **Known limitations** are tracked in `docs/known-limitations.md`. In particular,
  the new S3 cloud-backup path is verified in automated tests against an in-process
  mock object store; validation against a live S3, MinIO, or Backblaze B2 endpoint
  is recommended for your specific provider before relying on it.
