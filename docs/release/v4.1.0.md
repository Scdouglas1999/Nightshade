# Nightshade 4.1.0

A reliability and hardening release on top of 4.0. The headline work is a full
overhaul of catalog downloading and management; the rest is robustness across
remote discovery, weather, the headless API, and the native workspace.

## What's new

Catalog downloads and management. This is the big one. Downloading a star, deep
sky, or galaxy catalog used to overwrite the live catalog file the moment you
pressed Download, so a failed or interrupted download could leave you with a
broken catalog that still reported "Installed." Downloads now stage to a
temporary file and only swap into place once they're complete and verified, so an
existing catalog is never at risk. Progress survives leaving and returning to the
screen, large downloads stream to disk instead of buffering in memory, and any
download can be cancelled mid-flight. The catalog cards now show on-disk size,
version, object count, magnitude depth, what each catalog is actually used for,
and an "update available" hint. A separate bug where the planner insisted the
deep-sky catalog wasn't installed — even when it was — is fixed.

Remote discovery and pairing. More robust mDNS/network discovery and pairing on
the appliance and the desktop, with matching Avahi and systemd packaging updates,
so tablets and phones find a headless rig more reliably on the local network.
Saved servers and reconnection paths got cleanup as well.

Weather. A new Met.no cloud-cover provider with radar failover and transient-HTTP
retry, so the forecast and cloud sensors degrade gracefully instead of going
blank on a flaky connection.

First-launch location. The app can auto-detect your location by IP on first run,
so the planner and twilight math are sensible before you've entered coordinates.

Headless API hardening. Auth now fails closed on unrecognized scope names, the
`/api/info` route list advertises every registered route, and handler errors are
logged explicitly instead of being swallowed.

Quality and stability. Typed exceptions on the imaging and backend service
boundaries, 64 new native protocol tests (PHD2, INDI, Alpaca, rolling RMS), a
clean clippy gate and documented-unsafe pass across the Rust workspace, a large
analyzer-info cleanup, and several CI gates fixed (coverage, gate inputs,
baseline comparisons) so the release gate actually runs end to end.

The full itemized list is in `CHANGELOG.md`.

## Downloads

| Platform | File | Notes |
| --- | --- | --- |
| Android | `nightshade-4.1.0-android-universal.apk` | Sideload it (you'll need "Install unknown apps" enabled). One universal APK for all phones. |
| Linux | `nightshade-4.1.0-linux-x64.tar.gz` | Extract and run `./nightshade_desktop`. Includes the native bridge and libraw; needs GTK3. |
| Windows | `nightshade-4.1.0-windows-x64.zip` | Extract and run `nightshade_desktop.exe`. Includes the bridge DLL, libraw, and the MSVC runtime. |

Each file has a matching `.sha256` if you want to verify the download.

The Android APK is debug-signed, which is fine for sideloading but isn't a Play
Store build. As with 4.0, if a future release switches to a proper signing key
you'll have to uninstall and reinstall rather than update in place.

## Carried over from 4.0

The on-sky caveat from 4.0 still stands: the finishing and photometry algorithms
are tested against synthetic data and are internally consistent, but accuracy
hasn't been validated against real frames. If you submit measurements anywhere,
shoot a field with published comparison-star magnitudes first and confirm the
numbers land where they should. iOS and live cellular-push delivery still need a
Mac/Apple Developer account and your own Firebase/APNs keys respectively.
