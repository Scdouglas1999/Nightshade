# Nightshade 4.0.0

This release is about running a full imaging night from your phone and waking up
to a processed image instead of a folder of subs. Most of the work went into the
mobile app, the remote connection, the unattended autopilot, and the morning
processing pipeline.

## What's new

Remote control. You can run a whole session from the mobile app now: pick a
target, start the night, watch the live view, check the dashboard. There's also
an optional relay you can self-host, so phones reach the rig through an outbound
tunnel without a VPN or port forwarding. Relay connections are saved, so you're
not re-pairing every night.

Unattended autopilot. The sequencer can swap targets when one drops below the
horizon, handle the meridian flip, and run multi-night campaigns. A fair amount
of this release was closing safety gaps for running it while you sleep: a daylight
gate, safe-abandon on hardware faults, tracking restored after a flip, and
checkpoint resume that actually picks up where it left off.

Morning processing. By default you get a clean, unmodified linear master. There's
an opt-in finishing pipeline on top of that (registration, color calibration,
drizzle, deconvolution) and a "Night Doctor" pass that flags tilt, collimation,
and low-SNR problems with actual measurements rather than a thumbs up/down.

Science and photometry. The photometric calibration wizard now fits the
transform against the bundled star catalog instead of raw counts, using real
catalog magnitudes and exposure-normalized measurements, and falls back sensibly
when it can't solve for color from a single frame. There are new Science → Camera
settings for gain (e-/ADU) and saturation level, which feed both the rejection of
saturated stars and a more accurate limiting-magnitude estimate. The Image Grader
gained Max FWHM and eccentricity rules driven by per-frame PSF measurements, the
sky-to-pixel math is now a single shared projection, and exports are more honest
about provenance (AAVSO comparison/check magnitudes come from flux, the version
stamp is real, and the extinction FITS keyword is only written when it came from
an actual airmass fit). If you saved a photometric transform in an earlier build,
re-run the wizard — older transforms were fit on raw flux.

Mosaics. You can plan a mosaic, capture the panels under the same autopilot, and
stitch them with a native WCS stitcher, then review the result in the app.

Planetarium. The chart got a new dockable layout, a denser star catalog tier,
refreshed minor-planet elements, and work to cut the first-open stall.

Guider. The built-in multi-star guider now drops saturated, elongated, and
edge-of-frame stars, averages the rest with sigma-clipped flux weighting so one
jumping star doesn't throw the correction, and measures Dec backlash during
calibration.

Other hardware work. First pass at synchronized dual-rig imaging, a calibration
library manager, recovery when a device is unplugged mid-session, Home Assistant
auto-discovery, and cloud backup/sync.

Notifications. Server-side cellular push (FCM and APNs) is in for alerts when
something needs you. LAN/Wi-Fi push already works without any setup.

Appliance packaging. A systemd unit and installer, a Docker/compose setup, and a
Raspberry Pi (arm64) image with a first-boot Wi-Fi hotspot, if you want to run
Nightshade as a dedicated box.

Security. The dashboard and remote API got a hardening pass: CSRF protection and
HttpOnly cookies, constant-time token checks, a CORS allow-list, short-lived
WebSocket auth tickets, signed LAN-push manifests, and path allow-listing on file
browsing.

The full itemized list is in `CHANGELOG.md`.

## Downloads

| Platform | File | Notes |
| --- | --- | --- |
| Android | `nightshade-4.0.0-android-universal.apk` | Sideload it (you'll need "Install unknown apps" enabled). One universal APK for all phones. |
| Linux | `nightshade-4.0.0-linux-x64.tar.gz` | Extract and run `./nightshade_desktop`. Includes the native bridge and libraw; needs GTK3. |
| Windows | `nightshade-4.0.0-windows-x64.zip` | Extract and run `nightshade_desktop.exe`. Includes the bridge DLL, libraw, and the MSVC runtime. |

Each file has a matching `.sha256` if you want to verify the download.

A note on the Android build: the APK is debug-signed, which is fine for
sideloading but isn't a Play Store build. If a future release switches to a
proper signing key, you'll have to uninstall and reinstall rather than update in
place.

## Not in this build yet

Three things need accounts or hardware that aren't part of the codebase. The code
for each is in place; they turn on when you supply the missing piece (see
`docs/4.0-activation-checklist.md`):

- iOS. The companion app builds, but signing and submitting it needs a Mac and an
  Apple Developer account.
- Cellular push delivery. The server side is implemented and tested against a
  mock; live delivery needs your own Firebase project and an APNs key. LAN/Wi-Fi
  push works today.
- On-sky validation. The finishing algorithms are tested against synthetic data
  but haven't been run on real frames. Treat the first clear night as a tuning
  pass.
